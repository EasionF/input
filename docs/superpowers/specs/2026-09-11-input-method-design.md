# 基于 librime 的极简离线 Windows 拼音输入法 — 设计文档

- 日期：2026-09-11
- 状态：设计定稿（v1）
- 目标：一套单人自用、纯净离线、可扩展 AI 的 Windows 拼音输入法
- 非目标：商用打包/分发/货币化、macOS/Linux、云同步、多用户

## 1. 设计约束与硬边界

1.1 进程模型（与"双进程隔离"表述对齐）
- TSF TextService.dll 由 Windows 注入到**目标应用进程**内（Notepad/Word/Chrome 等），
  它不是独立进程。因此正确表述为：
  - TL 宿主（TextService.dll）：注入进程内，功能面**仅限**按键拦截(KeyEventSink)、
    组合(Composition)与上屏(Commit)。零 UI、零网络、零自研逻辑、无自有状态，
    只做代理转发。任何崩溃倾向逻辑一律外置。
  - Daemon.exe：常驻独立进程，承载拼音引擎、词库、D2D 渲染、AI、剪贴板清洗等
    全部复杂逻辑。
- 崩溃面：TL 宿主的职责被收窄到"读懂按键→转发→拿回候选/提交串"，即使 Daemon
  崩溃，TL 也只降级为直通（passthrough），不影响宿主应用键入手感。
- "崩溃率为零"承诺统一改写为："TL 侧无自研状态、无分配所有权、崩溃可自愈"。

1.2 文本流与 TSF 能力边界
- TSF 可靠能力（本项目只用这些）：
  - KeyEventSink：在组合期拦截并处理按键。
  - Composition：驱动候选组合串。
  - Commit：将最终字符串上屏。
- TSF **不提供**"提交后改写任意应用文本"。原地改写 / 划词 / 断行清洗这类能力
  只能在一条硬边界上实现：
  - UIA（UI Automation）+ 剪贴板快照/恢复。仅对暴露良好 UIA 的应用可靠。
  - 不可靠场景（终端、老 Win32、DirectWrite 控台、游戏）必须优雅降级：不做或
    提示不可用，绝不猜测。
1.3 隐私
- 核心打字纯离线，不连网。
- AI 侧车仅用用户自填 API Key，请求前经本地正则脱敏（API Key、银行卡、身份证、
  手机号等字段拦截/替换）。
- 无广告、无弹窗、无后台资讯。

## 3. IPC 契约

3.1 传输
- 共享内存：候选/上屏数据的单向高吞吐通道。
  - 采用**环形缓冲 + 版本化句柄（帧号）**。TL 端只读最新帧，不持有内存所有权。
  - 帧包含：候选列表、组合串、光标位置、属性（高亮/预编辑）等序列化结构。
- 命名管道：控制面（双向命令/应答），低频、带超时与重连。
3.2 消息（初步契约，实现期细化）
- 键型：`KeyEvent{ vk, scan, up/down, repeat }`
- 命令：`NotifyFocusChanged{ hwnd, title }` / `InvokeCandidate{ id }` / `AbortComposition`
- 域数据：`Frame{ version, candidates[], comp_str, caret, attrs[] }`

3.3 延迟预算
- 目标：本地打字 P99 上屏延迟 ≤ 12ms@单槽，极端负载可达 30ms 但不阻塞。
- IPC P99 目标 <1ms（共享内存路径），D2D 重绘独立于打字路径。
- 上线前必须有 benchmark 基准，不靠拍脑袋。

## 4. 词库与自适应学习（"高频词记忆"模块）

4.1 三层隔离
- 基��词库：只读 Double-Array Trie / FST；毫秒级精确匹配；本项目直接复用 librime
  自带的 schema + 词典（朙月拼音/自带 dict），不自行造词。
- 自适应用户库：LMDB（或 SQLite WAL），key=(上下文,候选)，存储打分/频次。
  半衰期衰减：Score' = Score·e^(-λΔt) + W_input。
- 热词/时事沙盒：外部导入数据包，独立沙盒，45 天硬 TTL 淘汰；仅高频打出的词
  晋升主库。

4.2 学习写回策略（防过度个性化 / 防灾难遗忘）
- 只记录"用户最终选定候选 + 触发上下文"为增量证据，不做隐式无证据改动。
- 每次用户明确选定候选 +N；未选但显示的候选衰减（由半衰期公式统一驱动）。
- 负反馈/误触策略做**阈值保护**：单一事件不立刻权重打折，累计多次负样本才降权；
  提供"撤销删除/回滚"入口，避免模型把用户真正想要的词永久压死。
- 学习仓储在 Daemon，绝不在注入进程。
4.3 大小上限
- 自适应库设容量上限，超出按 LRU + 衰减淘汰，防无限膨胀。

## 5. 候选面板与多模态扩展

5.1 主候选
- 第一层仅保留纯字词候选，禁止 emoji / 颜文字 / 无关联想污染盲打。
5.2 Ctrl+↓ 扩展抽屉
- 对当前光标处字词展开多模态：英文释义（CC-CEDICT）、emoji（语义匹配）、颜文字、
  粤语读音。
- 数据不做网络请求，全部本地资源。
- 粤语读音：librime 侧加载粵拼 schema 用于读音反查（复用引擎，不自建字典）。

## 6. AI 侧车 / 宏 / 主题

6.1 确定性宏（本地零延迟）
- /now /date /uuid /calc[表达式] 等。
6.2 AI 编译型工作流宏
- 用户以自然语言声明宏；LLM 编译为严格 JSON Workflow DSL。
- 运行时：触发宏 → 收集上下文变量({clipboard},{selection},{datetime},{input_param})
  → 调模型 → 流式在光标处上屏；Esc 截断。
- 依赖用户 API Key；无 Key 时相关入口置灰不生效。
6.3 划词 / 原地改写 / 翻译
- 基于 1.2 的 UIA+剪贴板快照边界实现，抓不到时降级。
6.4 主题
- AI 输出符合 Schema 的 Theme JSON；Daemon D2D 热重载；样式异常不影响引擎。

## 7. 排版 / 人物预设 / 进程记忆

7.1 排版开关（可独立启停）
- 盘古之白：中西文、数字间注入半角空格。
- 成对标点闭合 + 光标居中 / 防重复。
- 特定软件内强制半角标点。
7.2 Persona 配置包：以配置文件定义入库（程序员/文案/游戏/医学预设词频权重）。
7.3 每应用输入状态记忆 + 游戏静默
- 记忆 (exe/window title) ⇄ 中英状态，Daemon 侧持久化。
- 检测全屏/游戏进程时 TL 切 passthrough（不弹窗、不吞键、不显示候选）。

## 8. 错误处理 / 防御（全局）

- 全部 IPC 有超时/重连/版本握手；Daemon 崩溃则 TL 降级直通，自动拉起。
- 剪贴板快照：先读后写，写完恢复，异常时回滚；对"用户并发复制"竞态打日志不强行覆盖。
- 所有业务路径区分 业务错误 与 系统异常，保留上下文栈。
- 参数校验一律显式边界；禁止裸 any / 空 catch / swallow。

## 9. 技术栈
- C++（/20）− TL 宿主、Daemon、D2D、IPC。
- librime：C++ 拼音引擎（BSD-3，可放心用）。
- 局部管理脚本 / 配置：Rust 或 Python（自用工具，不做运行时依赖）。
- AI 调用：HTTP(S) 合规客户端 + JSON Schema 校验。
- 构建：CMake + vcpkg（拉 librime/依赖）；CI 本地脚本。

## 10. 里程碑（依赖排序，非"MVP 主义"，是真实依赖约束）
- M0 地基：CMake/vcpkg repo骨架、TSF 最小壳注册、三进程/IPC 骨架跑通、
  librime 集成、最少能"拼音→候选→上屏"闭环且宿主应用不崩。
- M1 打字核心稳固：候选面板 D2D、自适应词库、负反馈阈值、游戏静默、
  每应用状态记忆。
- M2 扩展面板：Ctrl+↓ 多模态、排版开关、Persona。
- M3 AI：宏、划词/改写、主题。

  拼图完整，再谈别的一切。
